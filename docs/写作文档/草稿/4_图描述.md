# 第 4 章配图画图说明（drawio 用）

> 本文档给出 4.1 与 4.2 节两张主图（`fig:dual-path-rag` 与
> `fig:code-gen-flow`）的画图指南，包括目标、布局、节点清单、连线清单与
> 配色建议。建议使用 [drawio](https://app.diagrams.net/) 矢量绘制后导出
> PDF（推荐）或 SVG / 高分辨率 PNG（≥ 300 dpi）。最终图片放在

> `\includegraphics[width=0.9\linewidth]{...}` 嵌入，图题用
> `\caption{}` + `\label{fig:xxx}`，配合 `\reffig{fig:xxx}` 引用即可。

## 一、`fig:dual-path-rag`：双通路 RAG 架构示意图

### 1.1 图的目标

用一张图说清楚两件事：

1. 通路 A（混合语义检索）与通路 B（确定性分级 + 硬链接）在数据流向上是
  并行的两条路径，分别处理"自然语言概念查询"与"数值阈值归属"两种本质
   不同的请求；
2. 两条通路最终在 LLM 上下文层面汇合，产出带引用源的自然语言回答。

### 1.2 整体布局

横向布局，左到右共四列。

```
┌──────────────┐ ┌──────────────────────────────┐ ┌────────────────┐ ┌─────────┐
│ 列 1：输入   │ │ 列 2：双通路并行             │ │ 列 3：上下文   │ │ 列 4：  │
│              │ │                              │ │ 组装           │ │ 输出    │
└──────────────┘ └──────────────────────────────┘ └────────────────┘ └─────────┘
```

- 列 1（最左）：上下两个输入框，分别表示自然语言查询与原始气象数值。
- 列 2 占整图约一半宽度，分上下两行：
  - 上行：通路 A 的 4 个节点（左→右）。
  - 下行：通路 B 的 3 个节点（左→右）。
- 列 3：单一节点 LLM 提示组装。
- 列 4：单一节点最终回答。

### 1.5 配色与字号

- 整图建议白底；不要使用渐变；同色系内只用一种深浅。
- 字号：节点正文 12 pt，旁注 10 pt，标题 14 pt（drawio 中以 px 为单位时
按比例缩放）。
- 字体优先 Microsoft YaHei 或 Noto Sans CJK SC（与论文 PDF 中文字体接近）。

### 1.6 drawio 实操提示

1. 新建 `docs/写作文档/figures/dual_path_rag.drawio`，用上述节点和连线一次
  绘完。
2. 全选后点击右侧 Arrange 面板的 `Edit Style`，统一调字号与圆角半径。
3. 文件 → 导出 → PDF（嵌入字体）或 SVG。
4. 主稿插入：
  ```latex
   \begin{figure}[!htbp]
       \centering
       \includegraphics[width=0.95\linewidth]{figures/dual_path_rag.pdf}
       \caption{双通路 RAG 架构示意图}
       \label{fig:dual-path-rag}
   \end{figure}
  ```

## 二、`fig:code-gen-flow`：代码生成与受限沙箱执行流程图

### 2.1 图的目标

用一张图说清楚两件事：

1. 用户的统计查询是怎样经过 LLM 代码生成、沙箱执行、结果回填这条闭环
  被处理成最终数值答案的；
2. 沙箱内部的四项关键约束（白名单 builtins、白名单 modules、daemon
  线程超时、结构化错误捕获）相对于"裸 exec"是什么位置，让评阅人一眼
   看出"安全边界"在哪里。

### 2.2 整体布局

纵向流程，从上到下分四层，外加右侧一条 `llm_direct` 对照支。

```
┌─────────────────────────────────────────┐
│ 第 1 层：输入                           │
└─────────────────────────────────────────┘
         │
┌─────────────────────────┐    ┌────────────────────────┐
│ 第 2 层（左）：代码生成 │    │  对照支：LLM 直算       │
└─────────────────────────┘    │  （禁止 codegen）       │
         │                     └────────────────────────┘
┌─────────────────────────┐                │
│ 第 3 层：受限沙箱执行   │                │
│  （灰色虚线大框圈住）   │                │
└─────────────────────────┘                │
         │                                 │
┌─────────────────────────────────────────┐
│ 第 4 层：评测器比对（oracle / scalar /  │
│ date+value / ordered_list ...）         │
└─────────────────────────────────────────┘
```

### 2.3 节点清单

主链路与对照支共 13 个节点。


| 序号    | 文本                                    | 形状      | 颜色（填充 / 描边）               |
| ----- | ------------------------------------- | ------- | ------------------------- |
| IN    | 用户查询 + 数据 (query, data)               | 圆角矩形    | #FFE6CC（浅橙） / #D79B00（深橙） |
| G1    | CodeGenerator functioncalling         | 矩形      | #DAE8FC（浅蓝） / #6C8EBF（钢蓝） |
| G2    | CodeGenResult code, reasoning         | 圆角矩形    | #F5F5F5（浅灰） / #666666（深灰） |
| S0    | 受限沙箱 executecode()                    | 大矩形（外框） | 透明 / #B85450（砖红） 虚线       |
| S1    | AST 解析 + def compute(data) 检查         | 矩形      | #FFF2CC（浅黄） / #D6B656（金黄） |
| S2    | 注入白名单 builtins 与 modules              | 矩形      | #FFF2CC（浅黄） / #D6B656（金黄） |
| S3    | daemon 线程 join(timeout=5 s)           | 矩形      | #FFF2CC（浅黄） / #D6B656（金黄） |

| EVAL  | 评测器比对 scalar / date+value / list      | 平行四边形   | #E1D5E7（浅紫） / #9673A6（灰紫） |
| OUT   | 数值准确率 llmwithcode 88.9 llmdirect 66.7 | 椭圆      | #E1D5E7（浅紫） / #9673A6（灰紫） |

### 2.5 关键视觉强调

- 用 #B85450（砖红）描边的虚线大框把 S1 / S2 / S3 / S4 / ERR 一起圈起来，框的右上
角贴一个 callout 标签：「轻量原型沙箱：屏蔽 open / eval / exec /
import，限可见模块为 math / statistics，墙钟超时 5 s」。
- 对照支用浅绿色，与主链路的浅蓝色形成视觉对比，立即让读者意识到右侧是
消融对照而非主链路一部分。
- 在 OUT 节点上方写两个独立的数据卡：
  - llmwithcode: 88.9 （绿色背景）
  - llmdirect: 66.7（红色背景）
- 在沙箱右下角再贴一行小字注：「daemon 线程超时后无法强行回收，详见 4.2.1
设计取舍说明。」

4. 同步导出 PDF + SVG（drawio 的 PDF 嵌入中文字体最稳）。

## 三、共用约定

- 文件存放：`docs/写作文档/figures/<short_name>.{drawio,pdf}`，drawio 源文件
随 PDF 一起提交；
- 论文中两张图的位置：
  - `\reffig{fig:dual-path-rag}` 在 4.1.1 节末尾段落（"借鉴 Lewis 等
  \cite{ref12} ... 整体结构如 \reffig{fig:dual-path-rag} 所示"）；
  - `\reffig{fig:code-gen-flow}` 在 4.2.1 节首段（"整个分析管线由三个
  组件协同完成，整体流程如 \reffig{fig:code-gen-flow} 所示"）。
- 字号：图内最小字号 9 pt，建议正文 12 pt；旁注 10 pt。
- 颜色统一沿用 drawio 的标准 6 色（橙 / 蓝 / 绿 / 黄 / 红 / 紫），全章保持
一致语义即可，不用追求视觉花哨。
