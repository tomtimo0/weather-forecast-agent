# 本科毕业论文答辩 PPT 大纲与讲稿

- **论文题目**：基于大语言模型的气象预报数据检索与分析智能体
- **目标时长**：5 ~ 7 分钟（实际 ≈ 6 分 25 秒，单页 30 ~ 80 秒）
- **总页数**：10 页（封面 + 8 张正文 + 致谢）
- **配色与版式**：建议使用学校官方答辩模板，主色蓝灰，副色橙红高亮关键数字；每页右上角放小尺寸学院 logo，页脚标注"姓名 / 学号 / 答辩日期 / 第 X 页"。
- **写作约定**：
  - "PPT 文字"= 实际打在幻灯片上的内容（含标题、要点、关键数字、配图说明），照抄即可。
  - "讲稿"= 答辩时口头讲述的内容，与 PPT 文字差别控制在 1.2 倍长度以内，避免"PPT 写一套、嘴里讲另一套"。
  - **数字处理原则**：每页**只保留 1 个标志性精确数字**作为锚点（便于评委同步核对论文表格），其余指标改用 "比较 / 数量级 / 趋势" 等自然语言描述（如 "超过九成"、"高出约二十个百分点"、"翻了一倍"），降低评委的认知负担。
  - 论文中所有精确数值仍以正文表格为准；本讲稿是面向答辩场景的"听感优先"版本。

### PPT 文字

**研究背景**
气象预报数据是支撑国民经济与社会发展的重要信息资源，但其获取与分析当前面临两类深层次技术鸿沟：
- 不同机构、平台之间的接口、字段、错误码不一致，带来**数据异构性**
- 数值数据到自然语言决策语义之间，存在**认知鸿沟**

**直接套用大语言模型的代价**
在数值边界判定、统计计算与权威引用三类任务上，存在引用编造、分级编造、数值漂移等明显的可信度问题。

**本文归纳的三类研究问题**
- **气象任务指令解析** —— 口语化输入到结构化 API 参数的鸿沟
- **气象数据异构特征** —— 多源 API 的字段命名、错误码、单位体系不统一
- **大语言模型数值与逻辑幻觉** —— 引用编造、分级编造、数值漂移

### 讲稿

> 气象预报数据是支撑国民经济与社会发展的重要信息资源，但其获取与分析当前面临两类深层次的技术鸿沟。一类是不同机构和平台之间，接口、字段、错误码不一致带来的数据异构性；另一类是数值数据到自然语言决策语义之间的认知差距。与此同时，把大语言模型直接套到气象数据分析上，会出现引用编造、分级编造、数值漂移等比较明显的可信度问题。本文据此把课题归纳为三个具体的研究问题：气象任务指令解析、气象数据异构特征处理，以及大语言模型本身的数值与逻辑幻觉。

### 版式建议

- 中 30% 列出三类查询场景的命中差异：概念性查询（向量主导）、实体名查询（BM25 主导）、混合查询（融合最优）。
- 下 30% 放结果数字与一句结论。

### PPT 文字

**通路 A：混合检索 + 可调权重融合**
承担**概念性查询的高召回**任务，覆盖术语解释、规范条文检索等场景。

**关键设计**
- 向量检索捕捉语义相似（应对同义改写）
- BM25 捕捉精确词法匹配（应对编号、缩写）
- 融合权重可调，按查询类别自适应

**评测结论**（60 条检索评测集，覆盖 8 类查询）
- Top-1 命中率 **达到 85%**，相比单通道有明显提升
- MRR 接近 0.91，证明正确条目通常出现在 Top-2 范围内

### 讲稿

> 第二项关键技术是双通路 RAG 架构，分两页汇报。先看通路 A，它承担概念性查询的高召回任务，把向量检索与 BM25 词法检索以可调权重融合。这样设计的好处是，向量负责捕捉同义改写，BM25 负责捕捉精确编号和缩写，两者互补。在 60 条检索评测集上，Top-1 命中率达到 85%，MRR 接近 0.91，意味着正确条目通常出现在前两位之内，相比单通道方案有明显提升。

## 第 6 页｜关键技术二：双通路 RAG —— 通路 B 语义桥接（约 60 秒，全文核心）

### 版式建议
- 上 35% 概念图：左为"数值输入（如 32 ℃ / 6 级风）"→ 中为"5 类确定性分级器（高温 / 低温 / 风力 / 降水 / 体感）"→ 右为"`grade_id` 硬链接 → 标准引用 + 等级名称"。
- 下 65% 放"桥接前 vs 桥接后"两栏代码块（论文 4.1 节那个）。左边模型自由发挥，引用被编造；右边通路 B 桥接后，附带真实国标编号与等级名称。整页配色把"红色虚假" vs "绿色真实"对比拉满。

### PPT 文字

**通路 B：5 类确定性分级器 + `grade_id` 硬链接**
承担**数值到等级到标准引用**的精确归属任务，从根本上消解条款编号编造。

**桥接前** —— 模型自由发挥
> "32 ℃ 已达到高温二级预警，依据 GB/T 20484 §3.0.4 ……"
> （**实际 GB/T 20484 是寒潮等级标准，不存在该条款**）

**桥接后** —— 通路 B 注入三段结构化标签
> `grade_id = heat_level_2`
> `citation = "GB/T 51120-2015"`
> `grade_name = "高温二级预警"`

**评测结论**（71 条桥接评测集，覆盖 9 类气象要素）
- 等级编号准确率与权威引用真实性 **同时全部正确**
- 与大语言模型自由发挥的基线在严格命中率上 **拉开七十多个百分点的鸿沟**

### 讲稿

> 通路 B 是本文的核心创新。它由 5 类确定性分级器加 grade_id 硬链接构成，承担数值到等级再到标准引用的精确归属任务。请看下方对比：桥接前模型会自信地引用一个根本不存在的条款编号，比如把高温预警挂到 GB/T 20484 上，而 GB/T 20484 实际上是寒潮等级标准；桥接后通路 B 给模型注入三段结构化标签——等级编号、权威引用、等级名称——把模型从"自由生成条款"的危险位置拉回到"复读结构化标签"的安全位置。在 71 条桥接评测集上，等级编号准确率和权威引用真实性同时全部正确，与大语言模型自由发挥的基线在严格命中率上拉开了七十多个百分点的鸿沟，从根本上消解了条款编号编造问题。

## 第 7 页｜关键技术三：代码生成 + 受限沙箱（约 40 秒）

### 版式建议
- 左 55% 流程图：用户统计请求 → LLM 生成 `compute(data)` 顶层函数 → 受限沙箱执行 → 结构化返回。
- 沙箱四重约束用四个小盾牌图标排列：白名单 builtins、白名单模块、墙钟超时、结构化错误捕获。
- 右 45% 放对照柱形图：18 条评测中 "代码执行档" vs "LLM 自由直算" 两根并列柱，差距用红色标注。

### PPT 文字

**轻量沙箱设计**：LLM 生成 `compute(data)` 顶层函数，在四重约束下执行
- 白名单 `builtins` —— 切断 `eval` / `exec` / `__import__` 等危险入口
- 白名单模块 —— 仅允许 `math` / `statistics` / `datetime`
- 墙钟超时 —— 单次执行 5 秒上限，超时自动终止
- 结构化错误捕获 —— 异常以 JSON 形式返回主智能体，触发重试

**评测结论**（18 条评测，覆盖 6 类统计模式）
- 代码执行档数值准确率 **接近九成**，达到 88.9%
- 比大语言模型自由直算 **高出约二十个百分点**
- 失败模式分析揭示了 LLM 在伴随状态维护与离散计数任务上的内在边界

### 讲稿

> 第三项关键技术是基于代码生成与受限沙箱的确定性统计分析。轻量沙箱由大语言模型生成 compute 顶层函数，在白名单 builtins、白名单模块、墙钟超时、结构化错误捕获四重约束下执行。在 18 条覆盖 6 类统计模式的评测集上，代码执行档数值准确率接近九成、达到 88.9%，比大语言模型自由直算高出约二十个百分点。失败模式分析也进一步揭示了大语言模型在伴随状态维护和离散计数任务上的内在边界，这部分也写进了论文的失败案例分析。
